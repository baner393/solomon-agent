# 第二轮：真实知识源与延迟验收

先完成本地只读检索，再接真实模型，最后与数字人共同测出声。离线模拟只检查协议和本地处理，不代表云端模型速度。

## 现有知识库接入

复制config.example.toml到不提交的config.local.toml。来源目录与data_dir分开；例如：

```toml
model = "your-model-id"
base_url = "https://your-provider.example/v1"
api_key_env = "SOLOMON_API_KEY"
data_dir = ".solomon-data-existing"
max_output_tokens = 512
history_char_budget = 6000

[sources]
existing_vault = "/absolute/path/to/your/vault"
```

路径从配置文件所在目录解析。按SETUP.md显式index，数据只落独立目录。默认仅索引非隐藏路径下的.md文件；.git/.kb/.obsidian/.trash及隐藏文件不读取，普通软链接指向内部隐藏文件也跳过，越界链接拒绝。媒体/OCR/新资料入库不在本轮范围。

实际知识、索引、测试快照和config.local.toml不得提交。调试时只汇报计数与耗时，避免复制私人正文到公开Issue/PR或日志。真实模型只收到问题、有限会话与最多3段摘录；不要把整库内容作为提示词。

## 准备真实模型

先确认服务商给出的OpenAI-compatible base_url和模型ID，不能沿用旧交接中的代理地址猜测当前服务。密钥在本地终端设置，不发到聊天或写入公开配置：

```bash
unset GIT_DIR GIT_WORK_TREE
read -r -s -p "API key: " SOLOMON_API_KEY
printf '\n'
export SOLOMON_API_KEY
```

在同一终端运行doctor只核对配置状态，再先用样例知识发一轮请求。确认兼容性后，才用真实知识配置检查答案质量。CLI失败保持非零退出；禁止因缺key静默转模拟。

## 分阶段测量

首文本表示首次获得新增回答文字；首句采用标点启发式，仍需数字人按最终句子切分方案确认；总时长表示本轮文本生成结束。ASR、TTS首音频与实际播放不在Agent内部计时。

每轮测速使用独立会话。模型参数、知识源大小、冷启动/热运行、样本数与网络环境均须注明。较少样本的P95只能描述当前样本，不能据此承诺语音目标。计时器不跨Windows/WSL直接相减。

## Windows与WSL连接

本机已用短时样例服务从Windows请求WSL loopback，验证/health与SSE事件顺序；这只证明本机当前配置可用。服务自动结束，未开放公网或常驻生产。服务默认监听127.0.0.1，实际端口与地址由部署配置决定，其他机器仍需独立验收。

数字人消费started/evidence/text_delta/completed等事件。停止时同时取消Agent请求和清空TTS/播放队列；新会话使用新session_id。联调接口仍以INTERFACE.md为准。

## 学习检查点

1. 为什么索引写入独立目录，原始知识仍然只读？
2. 为什么本地检索命中不等于生成答案的每句话都有依据？
3. 为什么模型首文本不能替代用户听到第一句话的时间？
4. 为什么低延迟首版先用预检索与一次生成，多步智能体循环留到明确需要时？

本轮得到测量方法与可复现入口后，再根据真实数据决定优化检索、模型参数、网络或TTS，避免凭框架名猜测性能。

## 2026-10-11 本地只读验收

本机WSL Ubuntu/Python3.14，授权源的212篇非隐藏Markdown接入独立索引；测试前后该范围的相对路径及内容哈希一致，没有新增、变更或删除。配置、索引和详细快照均未发布，未调用云端模型。

首次索引24.917秒；再次全文件哈希增量检查18.926秒，updated/removed均为0。三个普通关键词查询各重复20次、每次最多返回3段摘录，热检索P95为1.686至5.670毫秒。这只描述本地关键词检索，不代表问题理解质量、真实模型速度或完整语音延迟。

这个差异说明：资料扫描留在显式index或独立更新流程，实时请求只查已建索引。当前版本没有自动索引更新定时任务；资料新增后应显式重建增量索引。

## 测速入口

```bash
unset GIT_DIR GIT_WORK_TREE
PROJECT_DIR="$PWD"
"$PROJECT_DIR/.venv/bin/solomon-agent" --config "$PROJECT_DIR/config.local.toml" benchmark --demo --runs 5 --mode voice --message "智能体如何读取知识？"
```

真实配置准备好后去掉--demo，每轮会产生一次模型请求，默认5次，允许1至100。本入口测Agent文本处理，不包括进程初始化、HTTP传输、ASR、TTS及播放。首次查询可能含分词冷加载，应分别观察第一轮与后续轮。

报告仅含成功/失败计数、每轮首文本/启发式首句/结束耗时及最近秩P50/P95；不含问题、回答或证据正文。失败仍输出脱敏JSON并非零退出。simulation明确标记模拟；speech_measured恒为false；成功样本不足20时limited_samples为true，更多样本也不自动证明完整语音达标。

首句以中文句末标点、问号/叹号或换行启发式确认；英文句号等待空白或结束，避免小数误判。无句尾标点等completed再确认，sentence_at_completion为true。每轮独立会话、完成后归档，voice记录按30天规则清理；测速不永久销毁记录。

## 无需密钥的本地代理

已明确不需要认证的代理配置auth_mode = "none"，同时提供真实base_url与model。它不读取或转发密钥环境变量，并省略Authorization头。默认auth_mode = "api_key"仍要求密钥，不自动切换。SOLOMON_AUTH_MODE可显式覆盖；doctor显示认证模式，不显示凭据。

一般API配置按前文设置环境密钥；none模式无需设置SOLOMON_API_KEY。部署地址与模型ID留在不提交的本地配置，不能写死源码。首次真实请求使用仓库公开样例，兼容性通过后再测授权知识源。
