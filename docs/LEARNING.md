# 第一轮学习：从消息到有依据的回复

先运行 README 的离线演示，再按顺序做下列练习。练习只使用 examples/sample-vault 和独立测试数据，不连接生产渠道。

## 1. 看清四种职责

沿 CLI → knowledge → runtime → storage 追踪一次请求。找出哪里产生证据、哪里调用模型、哪里保存会话。解释为什么检索结果与模型回答不是同一件事。

完成标准：能说明KnowledgeProvider可更换，模型不直接拿到整个知识库。

## 2. 增加一条样例知识

在样例库加一条短笔记，更新索引，重新问相关问题。观察引用标题和摘录；随后更换数据目录，确认运行位置不依赖当前工作目录。

完成标准：理解来源目录只读与索引目录可写的区别。练习样本可编辑，生产来源不修改。

## 3. 比较来源与补充

问有依据的问题，再问样例库不覆盖的问题。查看 evidence 与完成元数据。讨论为何有相关笔记不等于每句话都得到支持，以及个人经历为何不能由常识推断。

完成标准：能区分知识库依据、模型补充和个人事实。

## 4. 观察流与取消

启动本地演示服务，用假数字人/测试客户端观察text_delta，再取消当前request_id。确认停止是生命周期操作，不只是把界面隐藏。

完成标准：取消请求后不继续投递迟到文本；新会话不带旧历史。

## 5. 阅读真实模型适配器

对照离线演示和PydanticAI生成器，找出base_url、模型、密钥与历史如何传入。密钥只从环境获取；未配置时明确失败。

完成标准：能解释『协议模拟通过』为何不能证明SenseNova或完整语音延迟达标。

下一阶段再学习模型自主工具调用、受限权限、长期记忆与后台任务。当前预检索工作流不是完整通用智能体，先让最小产品路径可靠。
