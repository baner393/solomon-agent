# 架构

消息 → 授权来源与会话 → 本地检索 → 一次流式模型生成 → 草稿或语音文本流。

## 分层

- config：配置文件与环境变量，绝对路径解析，来源和数据目录边界。
- knowledge：KnowledgeProvider、只读Markdown来源、独立SQLite索引；新来源可实现同一接口。
- storage：本项目会话与请求状态，不读取Hermes state.db。
- runtime：生成器适配器；真实PydanticAI与明确标注的离线演示可替换。
- api/cli：用户入口、SSE、取消、诊断与显式索引。

## 为什么预检索

普通草拟/语音问题先检索，再把最多3段摘录与必要上下文一次发给模型，避免用LLM规划检索又生成一遍回答。复杂多步任务以后再增加受限工具；当前不开放终端或任意文件写入。

当前来源通过Python标准SQLite和成熟中文分词接入，未安装旧Solomon的媒体/转写依赖。旧查询默认写vault/.kb且在import时绑定全局配置，所以新项目将知识来源与索引路径显式分离，避免把旧脚本作为只读API直接调用。

## 运行时选型状态

首轮已经采用PydanticAI，与Python检索处于同一运行环境。Pi能提供工具循环及SDK会话/压缩能力，但需要Node/TypeScript与Python接口管理；不能仅以『加网关』判断整个系统完成。Pi隔离实验已验证工具往返、文本增量、取消与应用自行保存恢复消息状态；没有验证coding-agent SDK持久会话、压缩或durable生产恢复。当前功能下尚未显示引入第二种运行环境的收益，因此保留为后续候选。当前端点兼容实验不能代替真实模型验收。

## 与数字人分工

数字人负责录音、ASR、交互、句子切分、TTS、播放、口型与端到端计时。Solomon Agent负责检索、有限上下文、唯一模型生成、依据和文本流。Windows/WSL地址通过配置确定；没有默认localhost互通保证。

## 数据与权限

来源只读，索引/缓存/会话落独立data_dir；来源与data_dir不得重叠。配置来源白名单，拒绝越界链接。服务首版为本地单用户，默认loopback，不作为已经带多租户认证的公网服务。

语音模式以来源与本次会话为依据，不自动带入旧渠道长期记忆。数字人内容日志保留30天；Agent会话存储与清理遵守同一语音期限。回复来源分类说明输入材料，不承诺逐句核验。
